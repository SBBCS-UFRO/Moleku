# Moleku Windows portable release

`Moleku.exe` is distributed as a portable Windows build: the user downloads a zip, expands it, and runs the app without installing Python, RDKit, or other libraries.

Distribution asset:

- `Moleku-Windows.zip`, containing the `Moleku/` onedir folder (`Moleku.exe` plus its dependencies)

## Local build

Use a dedicated build environment and the shared PyInstaller spec:

```powershell
$env:PYTHON = "C:\Miniforge3\envs\mcrg-build\python.exe"
scripts\build_windows_app.ps1
```

If `$env:PYTHON` is not set, the script falls back to `python` on `PATH`.

If PowerShell's default execution policy blocks the script (`Restricted`), run it via:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_windows_app.ps1
```

Recommended build environment:

```powershell
mamba create -y -n mcrg-build -c conda-forge python=3.11 rdkit pandas pillow numpy openpyxl reportlab pyinstaller
mamba activate mcrg-build
pip install customtkinter matplotlib
```

That produces:

- `dist\Moleku\Moleku.exe`
- `dist\Moleku\` (onedir folder with all dependencies)

## Smoke test

Validate that the frozen build launches before packaging:

```powershell
scripts\smoke_test_windows_app.ps1 "dist\Moleku\Moleku.exe"
```

The smoke test starts `Moleku.exe`, checks that the process stays alive, then stops it.

## Zip packaging

Create the distributable artifact with:

```powershell
Compress-Archive -Path "dist\Moleku" -DestinationPath "dist\Moleku-Windows.zip"
```

## Notes

- Unlike macOS, there is no `.app`/codesign/notarization step: the onedir folder is the deliverable. Windows SmartScreen may still warn on first run because the build is unsigned; users can proceed via "More info > Run anyway". Signing with an Authenticode certificate (e.g. via `signtool`) can be added later the same way `.github/workflows/release.yml` already conditionally signs the macOS build.
- The PyInstaller spec (`mcrg.spec`) already resolves a Windows icon (`images/moleku_simple_icon.ico`, generated by `scripts/generate_icons.py`) and only builds a macOS `.app` bundle when running on `darwin` — on Windows it produces the onedir folder directly, so no Windows-specific spec changes were needed.
